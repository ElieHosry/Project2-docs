UI/UX Goals Pool

Status: approved by the Design and UI/UX instructors (July 2026). Split out of the Design Goals Pool: all UI/UX goals now live here, graded by the UI/UX instructor only. This supersedes the July 15 arrangement (TU goals inside the Design track). Base goals are Games-flavored; the Category calibrations section covers all 10 categories.

How UI/UX goals work

There are no dedicated UI/UX students: Design students own these goals alongside their Design goals, within the same capacity (up to 3 goals per Design student per milestone, across both pools). Every team carries the commons — U1 ⭐ each milestone, plus U2 ⭐ in M2; the remaining U-goals are picks (instructor approval). Quality ladders as in the other track pools (Fail → Minimum Expectation → Exceptional; Fail = below the Minimum Expectation, i.e. the goal was not met).

Grading: every goal on this page is graded by the UI/UX instructor; the grades affect the owning Design student(s). The Design instructor grades only the Design Goals Pool.

Numbering: fresh U-numbers. Former labels: U1 ⭐ = the old TU1 ⭐; the picks were formerly Design D4/D10 (M1) and D3/D4/D10 (M2); M2 U2 ⭐ was formerly Design's M2 D1 ⭐. Pools are extensible like every other pool.

Milestone 1 (Research phase)

  • U1 ⭐ UI Standards & Wireframe Baseline — the minimum interface bar every team clears before production.
    Details & dependencies
    • Deliverable: Team-wide UI baseline: complete screen-flow map, control mapping to industry standards (touch-first for the mobile target), readability rules adopted (fonts, contrast, touch-target sizes), and a wireframe review session with the UI instructor.
    • Prerequisites: D1 ⭐; builds on M1 U2 / U3 where those are picked — but the baseline is due from every team regardless of picks. Where U2 is picked, the U1 review assesses those wireframes — no separate artifact is expected (one flow map serves both goals).
    • Feeds into: M2 U1 ⭐ and M2 U2 ⭐.
    • Quality ladder: Fail = below expectation — goal not met (missing, incomplete, or not to standard). Minimum Expectation = UI-instructor feedback incorporated and documented. Exceptional = wireframes usability-tested within M1.
  • U2 UX Flows & Wireframes — Menus → HUD — the screen map of the whole product before pixels get expensive.
    Details & dependencies
    • Deliverable: Complete screen inventory and navigation map (boot → menus → gameplay → fail/success loops), wireframes for all critical screens, HUD information hierarchy, user journeys per persona.
    • Prerequisites: D1 ⭐ (what screens the game needs).
    • Feeds into: M2 U2 ⭐ (polished UI), M2 U3 (motion design), CS M2 G5 (custom GUI system scope).
    • Quality ladder: Fail = below expectation — goal not met (missing, incomplete, or not to standard). Minimum Expectation = information hierarchy justified; journeys traceable per persona. Exceptional = wireframes usability-tested and iterated before M1 ends.
  • U3 Accessibility & Readability Foundations — legible fonts, sane contrast, touch targets that fit thumbs.
    Details & dependencies
    • Deliverable: Accessibility guideline set for the project (type sizes, contrast ratios, colorblind-safe palette rules, touch-target minimums, input alternatives) applied to the M1 wireframes.
    • Prerequisites: M1 D4 (wireframes to apply it to).
    • Feeds into: M2 D1 ⭐ (polished UI must comply), M2 D10 (mobile ergonomics).
    • Quality ladder: Fail = below expectation — goal not met (missing, incomplete, or not to standard). Minimum Expectation = verified with tools (contrast checkers, device tests). Exceptional = tested with users having relevant needs.

Milestone 2 (Iterated Prototype phase)

  • U1 ⭐ Functional UI & Usability — every menu works, on the mobile target, for someone who has never seen the game.
    Details & dependencies
    • Deliverable: In the showcase build on the mobile target: all menus function — Start, Pause (game actually pauses; cycle back to main menu available), "Resume Game" (exact label), "Quit Game" (exact label, with confirmation), "How to Play" screen accessible from the pause menu; touch equivalents replace PC-only conventions; critical HUD present and readable; first-time users can navigate unaided. The category-specific required-screen lists live in the Category adaptations below.
    • Prerequisites: M1 U1 ⭐; the M2 D1 ⭐ work; CS GUI capability.
    • Feeds into: The showcase demo; the T2 product's UI standard.
    • Quality ladder: Fail = below expectation — goal not met (missing, incomplete, or not to standard). Minimum Expectation = intuitive, clear layouts with evident feedback states. Exceptional = modern animated motion UI validated with first-time users.
  • U2 ⭐ UX Validation & Final Polished UI — tested with real users, polished to the "A" standard, running in the team's engine on the mobile target.
    Details & dependencies
    • Deliverable: Iterative UX testing across M2 with documented changes; complete menu functionality in the showcase build (start, pause, resume — exact labels, quit with confirmation, how-to-play); final polished UI implemented with the CS team — modern, animated, alive (not static screens); UI complies with the M1 accessibility guidelines; runs on the mobile target.
    • Prerequisites: M1 U2 (flows/wireframes), Design M1 D1 ⭐; CS M2 G5 or the CS GUI capability.
    • Feeds into: The trimester showcase; sets the visual/UX standard the T2 product must match.
    • Quality ladder: Fail = below expectation — goal not met (missing, incomplete, or not to standard). Minimum Expectation = coherent, branded, animated UI; test-driven iterations documented. Exceptional = "2025-style" motion UI (Persona 5 reference) fully in-engine.
  • U3 Menu & HUD Motion Design — menus that build, respond and breathe; HUD states that animate meaningfully.
    Details & dependencies
    • Deliverable: Motion spec (build-on animations, hover/press states, transitions, HUD state changes like health-bar reactions) plus implementation with the CS team in the engine.
    • Prerequisites: M1 U2 (flows), M2 D2 (visual language); CS GUI/graphics goals.
    • Feeds into: M2 D1 ⭐ (its Exceptional rung lives here).
    • Quality ladder: Fail = below expectation — goal not met (missing, incomplete, or not to standard). Minimum Expectation = implemented animated feedback on menus and HUD. Exceptional = cohesive motion identity across the whole product.
  • U4 Onboarding & Tutorial Design — the first five minutes: teach without a wall of text.
    Details & dependencies
    • Deliverable: First-time-user experience design: contextual teaching moments, how-to-play screen content, safe failure spaces; validated with players who never saw the game.
    • Prerequisites: M1 D6 (teaching beats) or D1 ⭐; a playable M2 build.
    • Feeds into: M2 D1 ⭐ (how-to-play requirement), showcase demo readiness.
    • Quality ladder: Fail = below expectation — goal not met (missing, incomplete, or not to standard). Minimum Expectation = new players succeed unaided in tests. Exceptional = tutorial invisible — taught entirely through play.
  • U5 Mobile UX Adaptation & Ergonomics — designed for thumbs, sessions and interruptions, on the reference device.
    Details & dependencies
    • Deliverable: Mobile ergonomics pass: thumb-zone layout, safe areas, session-length fit, interruption handling UX (calls/backgrounding), device testing on Pixel 8a/9a and/or mobile web.
    • Prerequisites: M1 D5, M1 D10; CS M2 G1 ⭐ (mobile build).
    • Feeds into: M2 D1 ⭐ (the polished UI must survive real hands on the real device).
    • Quality ladder: Fail = below expectation — goal not met (missing, incomplete, or not to standard). Minimum Expectation = interruption/resume UX handled gracefully. Exceptional = one-handed play validated with users.

Category calibrations

Per-category required screens for U1 ⭐ (M2); the Games base list lives in the goal above.

Education + Training

  • U1 ⭐ (M2) required screens: home / lesson select · in-exercise with pause · Resume and Quit (exact labels, quit with confirmation) · results/progress screen · settings · how-to-play/help · separate teacher and learner entry points where the product has both roles.

Simulator

  • U1 ⭐ (M2) required screens: home/scenario select · run view with pause & speed controls · results/report · settings · help. Resume/Quit labels apply to run sessions.

Fintech

  • U1 ⭐ (M2) required screens: home/dashboard · action flow (e.g. place order / add expense) with confirmation on anything money-like · history/reports · settings · help.

GovTech

  • U1 ⭐ (M2) required screens: citizen home · submit flow · status tracking · staff queue/dashboard view · settings · help — both roles navigable unaided.

Social Media

  • U1 ⭐ (M2) required screens: feed/home · composer · notifications · profile · settings · help — with designed empty states for a fresh account.

CMS

  • U1 ⭐ (M2) required screens: document list/home · editing canvas · preview toggle · publish flow with confirmation · settings · help.

Immersive Experience

  • U1 ⭐ (M2) required screens: minimal, diegetic-first UI: entry/attract screen · pause/exit · settings (volume, accessibility) · instructions — UI must not break immersion.

Creative Tools & Media Production

  • U1 ⭐ (M2) required screens: home/document manager · main editing workspace · export flow · settings incl. shortcuts · help/tutorial; the Quit-with-confirmation rule becomes an unsaved-changes guard.

Visualization & Analytics

  • U1 ⭐ (M2) required screens: home / board (dashboard) list · main data view with time-range & filter controls · view/dashboard composer · alerts & thresholds · settings · help. Resume/Quit labels apply to live/streaming sessions.
